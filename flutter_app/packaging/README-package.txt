TaskScheduler 0.1.0（Windows x64）—— 解压即用
=================================================

这是 TaskScheduler 的新 Flutter 桌面界面。任务分析、依赖校验、排序与评分仍由
原来的 C 内核完成；界面只是换成了 Flutter，并通过 ts_bridge.dll 调用它。


0.1.0 新增（本包）
----------------
1. 修复：任务清单在「全部 / 受阻」之间切换时的渲染错误。
   原因是列表把筛选结果存成了定长列表，而“已选中但被筛选隐藏”的任务需要补回列表，
   于是 build 期间抛出 Cannot add to a fixed-length list，整块列表面板不再渲染。
   现在改为可增长列表，并新增回归测试（先选中任务，再切到受阻）。
2. 设置 → 模型：删除探测按钮下方那句「连接地址或认证方式有未保存的修改：请先保存连接，
   再测试实际请求目标（测试只针对已保存的配置）。」；同一件事仍由下方那条橙色提示说明。
3. 设置 → 模型：「思考与输出」里的开关行不再显示鼠标悬停时那条整行宽的浅灰底色。
4. 版本号：产品 0.1.0 / 构建 0.1.0+10。

0.07 新增（上一包）
----------------
1. 可用时间弹窗（「可用时间与占用时间」）：
   - 每周可用时间、日期例外、课程/活动/休息占用共用同一个时间解析器：
     `8-12`、`08-12`、`8:00-12:00`、`08：00—12：00`、`8： 00 — 12：00，14-18`
     等价，规范显示为 `08:00-12:00, 14:00-18:00`；
   - 起止相同、`24:30`、`8:60`、残留乱码一律报错，不再「忽略后当作成功」；
   - 保留 `24:00`（日末）与 `00:00`（同样表示日末）的旧行为，跨午夜
     `22:00-02:00` 按既有分钟模型存为 1320→1560；
   - 多段自动排序、合并重叠后计算合计，输入时合计即时更新；
   - 滚动区域为滚动条留出固定空间；日期例外的「关闭/开放」与删除按钮之间有真实间距；
   - 底部「取消 / 保存并重新安排」统一高度、圆角、字号，文字居中；
   - 删除了「每周规则按此偏移…」「空白的星期表示不可用…」两处说明，规则不变。
2. 材料识别改为**真实模型请求**（新增 `ts_bridge_constraints_async` 作业，有自己的
   提示词与结果校验器，不塞进任务 schema）。它看到的是本次材料 + 已提交的用户补充 +
   已上传附件的提取文本（课程表、活动、休息都会进入上下文），并区分
   「可用时间 / 课程活动休息占用 / 日期例外 / 尚不能确定」：
   - 识别到的候选**默认全部不勾选**，只有勾选并保存才写入正式数据；
   - 课程不会被当成可工作时间；「中午和晚上各吃饭半小时」只给时长、没有起点时是
     可编辑的待确认项（需要你补时段），程序不会替你猜一个时刻；
   - 结果按材料签名缓存：反复打开弹窗不会重复发起请求，只有点「重新识别」才会；
   - 失败、取消、材料变化、会话切换都不会污染现有数据，更不会降级成「全时段可用」。
3. 图标与按钮分层：普通图标（会话更多、折叠侧栏、导出/分享、新建、输入区展开）

4. 菜单统一：会话右键、会话「更多」、日历片段右键与左下角用户菜单使用同一套样式

一、直接运行
------------
双击 taskscheduler.exe。

同目录的 config.json 已配置云端模型。若打包者内置了密钥，可直接运行；否则请在“设置 → 模型”中为自己的连接输入 API Key（只写入 Windows 凭据管理器）。


二、目录内容
------------
  taskscheduler.exe       主程序
  flutter_windows.dll     Flutter 运行库（必需）
  data\                   界面资源与 AOT 代码（必需，请勿删除）
  ts_bridge.dll           与 C 内核的桥接库（必需）
  libcurl-x64.dll         网络传输（必需）
  cacert.pem              TLS 根证书（HTTPS 必需，请勿删除）
  config.json             云端模型配置（是否内置密钥取决于打包方式，见下方）
  config.example.json     不含密钥的配置模板
  VERSION.txt             版本与构建信息
  MANIFEST.sha256         包内每个文件的 SHA-256


三、安全提示（请务必知悉）
--------------------------
若打包时传入了密钥，本包的 API Key 会明文写在 config.json 的 "api_key" 字段里。
这意味着：任何拿到这个压缩包的人都能使用该密钥并消耗其额度。0.05 默认使用 `-NoApiKey` 打无密钥包，由用户在“设置 → 模型”里输入。

  - 不要把本包上传到公开仓库、网盘分享链接或任何公开位置；
  - 只在自己可信的机器之间传递；
  - 需要分享给他人时，请先删掉 config.json 里的 "api_key" 行，
    改用环境变量：把 config.json 的 "api_key_env" 设为 "DEEPSEEK_API_KEY"，
    并在系统里设置同名环境变量（设置后需重启程序）；
  - 若密钥已外泄，请到服务商控制台吊销并重新签发。

程序本身不会把密钥写入会话历史、导出文件或日志；导出里只记录密钥**来源**
（config_inline / env / none）与是否存在，绝不写内容。


四、使用要点
------------
1. 在底部输入框粘贴材料，或点输入框**左下角的「+」**添加文本文件。
   文件选择用的是 **Windows 系统对话框**（支持快速访问、网络位置、键盘操作），
   选择器支持 TXT / MD / PDF / DOCX / PPTX；选中的文件会以**蓝色链接**显示在输入框上方，点它可移除。
    0.05 支持本地提取 TXT / MD / PDF / DOCX / PPTX；扫描 PDF 不支持 OCR，旧 .doc/.ppt 不支持。
2. 点输入框**右下角的箭头**开始分析（也可 Ctrl+Enter）。输入框高度固定，
   文字超过可视范围时在框内滚动，不会把界面撑开。
3. 等待时只显示「正在思考 · 用时」和停止按钮，
   不显示模型思考正文，也不显示虚构的百分比。
4. 超过 120 秒会提示「继续等待 / 取消请求」，继续等待不会重新发送请求。
5. 结果到达后：左侧是任务清单（勾选框记录你自己的完成状态），
   右侧可在「依赖图 / 甘特图」之间切换。
   - 依赖图：完整依赖 DAG，多前置关系全部保留；支持缩放百分比/实际大小/适应全部/定位当前；
   - 甘特图：横轴是相对累计工时，不是日历时间；工时未知的任务不给确定起止时间。
6. 悬停任务约 0.3 秒出现详情预览；单击固定详情；Esc 或点空白处关闭。
   详情里的前置/解锁任务可以点击跳转，会真正滚动清单并把图平移到目标。
7. 完成任务后勾选框会立即本地重排，**不会重新调用模型**。
8. 再次发送内容就是对同一会话的补充要求：会生成新版本，旧版本保留，
   可在顶部「版本 x/y」里回看（历史版本只读）。
9. 顶部「导出」：
   - 「导出任务计划（TXT）」是日常交付物，只有任务事实与自然语言安排原因；
   - 「导出结构化诊断（JSON）」保留内部评分与权重，仅供排查，不要当交付物。


五、数据保存在哪
----------------
默认保存在**本程序所在目录**下的：

  TaskSchedulerData\

整个文件夹可以连同数据一起搬走（便携）。

如果程序目录不可写（例如放进了 C:\Program Files），会按以下顺序自动改用别的位置，
界面上**不会**弹任何提示：

  %LOCALAPPDATA%\TaskSchedulerFlutter → %APPDATA%\TaskSchedulerFlutter
  → %TEMP%\TaskSchedulerFlutter

想指定位置，就设置环境变量 TASKSCHEDULER_DATA_DIR 指向一个可写文件夹。

只有一种情况会提示：所有位置都不可写。此时程序仍可正常使用，但顶部会说明
「本次运行不保存历史」。

删掉 TaskSchedulerData 目录等于清空历史会话，不影响程序运行。
原始附件移动或删除后，会话里已保存的文本仍可用于后续补充要求。


六、常见问题
------------
启动提示「无法启动 / 找不到 ts_bridge.dll」
  → 请确认是**整个文件夹**一起解压后再运行，不要只拷贝 exe。

提示「缺少密钥」或「配置要求提供密钥，但当前读取不到」
  → config.json 被改动过；恢复 "api_key" 字段，或设置 "api_key_env" 指向的环境变量
    后重启程序。

提示「缺少 TLS 根证书包」
  → cacert.pem 必须与 exe 同目录，或在配置里用 ca_bundle_path 指定。

提示「模型输出校验失败」
  → 直接给出结构不合格的结果；程序已自动请求过一次修复。
    可换模型，或把材料拆小一点。

想离线试用（不联网、不计费）
  → 把 config.json 的 "mock_mode" 改为 true，重启程序即可。

八、0.05 设置与新增功能
----------------------
- 首次启动会用 config.json 生成一个“旧配置”模型连接（完整端点原样保留，不自动拼 /v1）；
  内联 api_key 会一次性导入 Windows 凭据管理器，config.json 本身保持原样。
- 之后的模型连接、API Key、思考模式、主题、字号、通知等都在左下角“设置”里管理。
  API Key 只写入系统凭据管理器，设置文件、会话、备份、日志与诊断都不含密钥。
- 更换连接地址后必须重新输入 API Key；旧密钥不会被发往新主机。
- “账户安全”页本期只有未接入说明与禁用表单，不是登录系统，也不影响本地分析。
- 备份在“设置 → 存储”里生成，不含密钥；恢复后需要重新输入 API Key。
- 0.05 新增：会话重命名/置顶/归档/最近删除、搜索、可自定义快捷键、任务搜索/筛选/日期/分钟/
  前置搜索、输入区手动展开、版本差异、存储迁移（复制+校验，重启切换）、Windows 通知。
- 系统通知由 Windows 通知中心决定是否显示；被系统拒绝时程序会明确提示。
